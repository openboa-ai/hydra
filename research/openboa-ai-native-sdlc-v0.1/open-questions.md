# Open Questions

These questions require canary evidence or later platform capability. They do not block a portable v0.1 design.

## Evidence gaps

- Which measures best predict that an agent role can lead a larger class of work without increasing escaped defects or review burden?
- How should creative disagreement and problem reframing be evaluated without rewarding agreement with the original prompt?
- When does parallel delegation reduce total time after coordination and review cost are included?
- Which parts of a role's learning can be safely shared across repositories without leaking private context or turning temporary preferences into policy?
- What minimum observation window is useful across documentation, UI, deployment, and operational work?
- Which independent incident reports provide enough detail to test current vendor security claims?

## Platform questions

- When Codex Goals, GitHub issue fields, Agentic Workflows, or connector capabilities change, which current template fields can move into native structured state?
- What evidence threshold should allow a stable manual skill to become a scheduled task, Codex Action, or GitHub Agentic Workflow?
- How should an agent role be shown in GitHub when the role is not represented by an assignable GitHub account?

## Canary decisions

- Choose one bounded Ouroboros goal to test multi-session and cross-repository continuity.
- Choose one Coffee Chat goal to test agent-led problem framing and creative product judgment.
- Decide the acceptable human-attention budget and failure boundary before each canary begins.

## Human gate

Approve the doctrine, responsibility model, plugin skill boundary, and migration together. Later evidence may change the current method; it must not silently rewrite the doctrine or widen authority.
