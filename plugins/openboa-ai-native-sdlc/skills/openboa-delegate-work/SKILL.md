# Delegate Work

Create an assignment that lets a capable work lead succeed without constant supervision.

1. Understand the purpose, desired outcome, priorities, and why the work matters. Resolve material conflicts instead of converting them into a longer task list.
2. Name one work lead. The lead may be a human or agent role. State why the lead is suited to this work and where it may need support. Inherit OpenBoa's accountable human from the operating model; name another human only for a specifically delegated decision.
3. Match responsibility with decision rights, context, repositories, tools, environments, access, time, budget, and dependencies. If any are missing, fix the assignment or narrow the outcome.
4. Set boundaries from impact, reversibility, trust, and available checks. Name the exact decisions the lead may make and the exact conditions that return to a human.
5. Define observable acceptance evidence and post-delivery observation. Do not prescribe the implementation method unless it is a real constraint.
6. Use one GitHub parent Issue for substantial work. Add sub-issues only for a separate lead, review surface, or dependency. Create a Codex Goal only when the user explicitly asks Codex to track one.
7. Confirm the lead understands or challenges the assignment before treating it as ready.

Read [doctrine](../../references/doctrine.md), [operating model](../../references/operating-model.md), [workflow](../../references/workflow.md), and [GitHub](../../references/github.md). Start from the [Goal Issue template](../../assets/goal-issue.md).

Return the complete assignment, work lead choice, authority, resources, boundaries, evidence, dependencies, and first handoff to the work lead.
