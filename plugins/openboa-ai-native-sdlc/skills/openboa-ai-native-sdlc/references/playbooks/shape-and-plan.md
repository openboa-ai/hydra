# Shape and plan

**Change rate:** fast. This is a replaceable method, not doctrine.

Use this playbook when a request needs research, clarification, design, decomposition, or a durable plan.

## Shape the outcome

Begin with the reason the work matters and the observable change that should exist. Separate:

- purpose and principles that constrain the work;
- the desired outcome and acceptance evidence;
- known facts and assumptions;
- boundaries, dependencies, and external effects;
- decisions already made and decisions still open.

Investigate what the repository and environment can answer before asking the human. When several product meanings remain plausible, present the alternatives, evidence, recommendation, and consequence of each choice. Ask for one direction decision, then resume agent-led work.

## Plan as a current hypothesis

Build a plan large enough to deliver a coherent outcome. Do not turn every file or command into a work item. Update the plan when evidence changes the route.

Use:

- one parent Issue for the outcome when durable coordination is needed;
- a sub-Issue only when its result can be delegated, verified, and integrated independently;
- a dependency link when one result truly blocks another;
- an isolated branch or worktree for each conflicting change surface;
- an explicit synthesis step when parallel work must converge.

Record acceptance evidence before implementation. Include tests, evals, preview or running-surface evidence, delivery state, and post-delivery observation as appropriate.

## Choose leadership and topology

- **Agent-led:** the outcome is clear and the work is bounded, observable, reversible, and within existing authority.
- **Joint:** the agent can explore and recommend, but a choice changes product meaning, values, policy, or material tradeoffs.
- **Human-led:** the decision sets purpose, priority, policy, authority, or an irreversible external commitment.

Stay single-agent for sequential, shared-state, or tool-dense work. Use parallel agents only when tasks are independently describable, isolated, and verifiable, and when synthesis costs less than the time saved.

## Planning evidence

Before execution, the work should have an outcome, acceptance evidence, known boundaries, current repository/base, dependencies, chosen topology, and the first safe action. A plan does not need ceremony; it needs enough truth for another collaborator to continue.
